# Локализация: провайдер и каталог сообщений

С 2.0.0 кит говорит по-английски по умолчанию и знает про другие языки. До 2.0.0
русские подписи были зашиты в дефолты пропсов, и другой язык означал передать
подпись в каждом месте вызова.

## Порядок разрешения строки

```
проп компонента  →  сообщение провайдера  →  английский фолбэк в коде
```

Проп побеждает всегда: он точечное переопределение, а не единственный способ.
Фолбэк лежит в коде и в бандле — без него компонент без провайдера рисовал бы
пустоту вместо подписи.

## Подключение

Кит **не грузит каталоги сам** — иначе русский оказался бы в бандле у всех,
включая тех, кому нужен только английский. Каталог импортируется явно:

```tsx
import { UiProvider } from "@olddevs/ui";
import ru from "@olddevs/ui/locales/ru";

<UiProvider locale="ru-RU" messages={ru}>
  <App />
</UiProvider>;
```

Оба пропа нужны и отвечают за разное:

| Проп       | За что отвечает                                   | Без него                         |
| ---------- | ------------------------------------------------- | -------------------------------- |
| `messages` | подписи кита                                      | английские строки из фолбэка     |
| `locale`   | формат дат, чисел, единиц и выбор формы склонения | локаль приходит сверху, см. ниже |

`messages` без `locale` даёт русские подписи с датами в формате браузера — почти
наверняка не то, что нужно.

Английский подключать не требуется: он и есть фолбэк. `@olddevs/ui/locales/en`
существует ради симметрии — код, выбирающий каталог по языку пользователя, не
должен спотыкаться на том, что для одного языка импорт есть, а для другого нет.

## Частичное переопределение

Каталог можно донести кусками: недоданные ветки берутся из фолбэка.

```tsx
<UiProvider messages={{ confirmDialog: { confirm: "Yes, delete" } }}>
```

Вложенный `UiProvider` наследует всё от внешнего и переопределяет то, что задал
сам, поэтому окно со своей локалью работает внутри приложения на другом языке.

## Если у вас уже есть `I18nProvider` из react-aria

Обычный случай: приложение держит свой `I18nProvider`, потому что использует
react-aria напрямую. Кит с ним не спорит.

**Без `locale` кит не разворачивает свой `I18nProvider` вовсе** — локаль берётся
у вашего. Это сделано намеренно: кит, навязывающий `en-US`, заставил бы
датапикеры говорить не на языке остального приложения.

```tsx
<I18nProvider locale="de-DE">
  <UiProvider messages={de}>…</UiProvider>
</I18nProvider>
```

Здесь даты и календари будут немецкими, подписи — из вашего каталога. Передайте
`locale` в `UiProvider`, только если хотите перебить внешнюю локаль для поддерева.

## Без провайдера

Кит работает и так: все строки английские, форматы дат — из локали браузера.
Отдельно оборачивать одну кнопку не нужно.

## Что не считается переводом

Три вещи проходят мимо каталога намеренно:

- **Раскладка `Keyboard`.** Массив `["Й","Ц","У",…]` говорит, какие символы
  клавиатура вводит, а не на каком языке она подписана. `layout="ru"` работает
  при `locale="en"` и наоборот.
- **Единицы измерения.** Размер файла форматируется `Intl.NumberFormat` со
  `style: "unit"`: «МБ» и «MB» — одна единица по правилам локали, а не две
  строки для перевода.
- **Тексты исключений.** `throw new Error("Unknown period")` читает разработчик
  в стектрейсе, а не пользователь на экране.

## Как добавить строку

1. Ключ в [`src/i18n/messages.ts`](../src/i18n/messages.ts) — в пространство
   имён своей семьи; если подпись значит то же самое в двух местах, она идёт в
   `common` и не дублируется.
2. Значение в [`src/i18n/defaults.ts`](../src/i18n/defaults.ts) (английское) и в
   [`src/locales/ru.ts`](../src/locales/ru.ts).
3. В компоненте — `useMessages()`, и `проп ?? messages.семья.ключ`.

Параметризованное сообщение — **функция**, а не шаблон в формате ICU MessageFormat:
`collapsed: ({ count }) => …`. Склонение делает `Intl.PluralRules` внутри файла
локали: правила знает локаль, а не компонент. Компонент, считающий окончания,
умеет ровно один язык.

Гейт [`tests/i18n-gate.test.ts`](../tests/i18n-gate.test.ts) падает и на
литерале мимо каталога, и на ключе, забытом в русской локали.

## Хуки

| Хук             | Что даёт                                                              |
| --------------- | --------------------------------------------------------------------- |
| `useMessages()` | весь каталог; читайте `messages.pagination.next`, а не строковый ключ |
| `useUiLocale()` | локаль для `Intl`: явная → `I18nProvider` потребителя → браузер       |
| `useUiConfig()` | `dir`, контейнер порталов и плотность по умолчанию                    |

## Плотность

С 2.2.0 `UiProvider` принимает `density` — `"comfortable"` или `"compact"`.
Это **умолчание, а не режим**: проп `DataTable` и состояние таблицы значение перекрывают, а
провайдер избавляет приложение с пятью таблицами от пяти одинаковых пропов.

Цепочка разрешения устроена так же, как у строк каталога:

```
проп DataTable → состояние таблицы → провайдер → умолчание кита (comfortable)
```

Проп `density` появился только в 2.2.0, хотя обещан был ещё в 2.0.0:
ADR-0002
откладывал его до появления читателя, и `DataTable` им стал. Разбор —
ADR-0023.

## RTL

`UiProvider` принимает `dir` и публикует его, но **компонентной поддержки RTL (письма
справа налево) в ките нет**: ни один компонент не отражает раскладку. Проп заведён, чтобы контракт
не пришлось ломать, когда заказчик появится. Пока его нет, `dir="rtl"` изменит
только то, что вы сделаете с этим значением сами.
