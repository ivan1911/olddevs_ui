# VirtualGrid

## Кратко для AI

Сетка карточек с виртуализацией: в DOM живут видимые ячейки и небольшой запас вокруг.
Прокручивает **свой контейнер** (`scroll="container"`, высоту задаёт потребитель)
или **окно браузера** (`scroll="window"`). Ячейка — любой узел; кнопки в ней законны.
Подгружает страницы при подходе к концу и выделяет ячейки протяжкой пальца.

## Когда использовать

- Сотни и тысячи превью: картинки, документы, обложки.
- Экран с большой сеткой на прокрутке страницы, с липкой шапкой и подгрузкой — `scroll="window"`.
- Сетка в выделенной области с известной высотой — `scroll="container"`.

## Когда не использовать

- Для десятка карточек: обычный CSS-грид проще.
- Для таблицы данных — это `DataTable`.
- Для сетки, которую нужно сортировать перетаскиванием: виртуализация и
  перетаскивание вместе в ките не проверены. Протяжка пальцем (`dragToSelect`) —
  выделение, а не перенос.

## Минимальный пример

```tsx
import { VirtualGrid, MediaCard } from "@olddevs/ui";

<VirtualGrid
  items={images.map((k) => ({
    id: k.id,
    textValue: k.name,
    content: <MediaCard preview={<Image src={k.url} alt="" />} title={k.name} />,
  }))}
  aria-label="Картинки"
  minItemWidth={180}
  minItemHeight={220}
  className="h-[520px]"
/>;
```

## Пропы

| Проп                | Умолчание     | Назначение                                                                    |
| ------------------- | ------------- | ----------------------------------------------------------------------------- |
| `items`             | —             | Ячейки: `id`, `content`, `textValue`, `contextMenu`.                          |
| `aria-label`        | —             | **Обязателен.**                                                               |
| `minItemWidth`      | `180`         | Наименьшая ширина ячейки, пиксели. Из неё считается число колонок.            |
| `minItemHeight`     | `180`         | Наименьшая высота ячейки, пиксели. Если содержимое выше, растёт и ячейка.     |
| `gap`               | `12`          | Зазор между ячейками, пиксели.                                                |
| `edgeGap`           | `true`        | Отступ `gap` по краям сетки; `false` — крайние ячейки вплотную.               |
| `maxColumns`        | —             | Предел числа колонок.                                                         |
| `emptyText`         | —             | Что показать при пустой сетке.                                                |
| `scroll`            | `"container"` | Что прокручивается: свой контейнер или окно браузера — см. ниже.              |
| `offsetVar`         | `--topbar-h`  | Переменная высоты липкой шапки (режим `window`), как у `SelectionBar`.        |
| `selectionMode`     | `"none"`      | Ось выбора: `single`, `multiple`.                                             |
| `selectionBehavior` | `"toggle"`    | `toggle` — клик переключает; `replace` — как в файловом менеджере.            |
| `rangeSelection`    | `"replace"`   | Диапазон по Shift: заменяет выбор (`replace`) или добавляется к нему (`add`). |
| `selectedKeys`      | —             | Выбранные ключи (`Selection` react-aria); состояние держит потребитель.       |
| `onSelectionChange` | —             | Новый набор выбранных ячеек; отдавайте его обратно как пришёл.                |
| `dragToSelect`      | `false`       | Выделение протяжкой пальца. Только с `selectionMode="multiple"`.              |
| `onAction`          | —             | `(id, { rect }) => void` — ячейку открыли: клик, Enter, касание.              |
| `onLoadMore`        | —             | Подгрузить следующую страницу — когда до конца меньше высоты видимой области. |
| `isLoadingMore`     | `false`       | Идёт подгрузка: под последней строкой индикатор.                              |
| `loadingMore`       | крутилка      | Свой индикатор подгрузки, например ряд скелетонов.                            |
| `className`         | —             | Классы сетки. В режиме `container` **высоту задаёт потребитель**.             |

Размеры числами, а не классом `Size` из react-aria: класс библиотеки в публичном
API кита обязал бы потребителя импортировать его ради двух чисел.

## Прокрутка: свой контейнер или окно

**`scroll="container"`** (по умолчанию) — сетка прокручивает себя. Потребитель
обязан задать ей высоту — `h-[520px]`, `flex-1` внутри колонки, что угодно
определённое. Без высоты сетка вырастет по содержимому, и прокручивать будет
нечего.

**`scroll="window"`** — сетка растёт по содержимому, прокручивается страница, а в
DOM по-прежнему только ячейки в видимой области: виртуализатор react-aria сам пересекает
свою область с окном. Это режим для такого экрана: с липкой шапкой и нижней панелью.

```tsx
<VirtualGrid items={items} aria-label="Фото" scroll="window" onLoadMore={loadMore} />
```

**Липкая шапка.** Когда клавиша-стрелка уводит фокус за верх окна, ячейка не
оказывается под шапкой: сетка держит отступ, заданный CSS-переменной из
`offsetVar`. По умолчанию это `--topbar-h`, её публикует `TopBar`; та же
переменная у `SelectionBar` и `useStickyOffset`
(ADR-0016).
Если шапка своя, опубликуйте её высоту в эту переменную или передайте имя своей
в `offsetVar`.

**Замер:** 3000 ячеек в режиме окна — в DOM от 95 до 155; при прокрутке набор
отрисованных ячеек смещается. Проверяется в браузере: в jsdom раскладки нет, и
виртуализатор не отрисовывает ничего
(ADR-0028,
дополнение).

## Подгрузка страниц — `onLoadMore`

```tsx
<VirtualGrid
  items={items}
  aria-label="Фото"
  scroll="window"
  onLoadMore={() => fetchNextPage()}
  isLoadingMore={isFetchingNextPage}
/>
```

Сетка вызывает `onLoadMore`, когда до конца загруженного остаётся меньше высоты
видимой области (или контейнера), и повторно — после каждой новой страницы,
пока конец близко. Повторный вызов во время подгрузки возможен: признак «уже грузим»
держит потребитель, как и признак «больше нечего». Пока `isLoadingMore`, под
последней строкой стоит индикатор — крутилка кита или свой `loadingMore`.

В тестах на jsdom с `onLoadMore` нужна заглушка `IntersectionObserver`: датчик
подгрузки стоит на нём, а в jsdom его нет.

## Колонки считает раскладка

`GridLayout` берёт ширину сетки и наименьший размер ячейки. Ни `matchMedia`, ни
`ResizeObserver` в коде кита нет: число колонок — вывод раскладки, а не наш
расчёт. `edgeGap={false}` снимает отступ по краям — сетка «1fr без полей».

Роли (`grid` с `data-layout="grid"`, `row` и `gridcell` у ячеек), клавиатуру и
поиск набором тоже обеспечивает react-aria. Своими руками роли не проставляются: тогда
клавиатура перестала бы соответствовать объявленной разметке. До 3.47.0 сетка
была `listbox` с `option` — см. [заметку о миграции](../../api/migration-notes.md).

## Выбор — у сетки, а не у ячейки

Ось включается явно, пропом `selectionMode` (`single` или `multiple`).
Выбранные ключи держит потребитель и передаёт парой `selectedKeys` /
`onSelectionChange` — кит даёт форму, состояние остаётся снаружи
(ADR-0023).

```tsx
const [selected, setSelected] = useState<Selection>(new Set());

<VirtualGrid
  items={items.map((p) => ({
    id: p.id,
    textValue: p.name,
    content: (
      <MediaCard
        preview={<Image src={p.url} alt="" />}
        title={p.name}
        selected={selected === "all" || selected.has(p.id)}
        actions={<Checkbox slot="selection" label={`Выбрать ${p.name}`} />}
      />
    ),
  }))}
  aria-label="Картинки"
  selectionMode="multiple"
  selectedKeys={selected}
  onSelectionChange={setSelected}
  className="h-[520px]"
/>;
```

**Флажок выбора — `Checkbox slot="selection"`** в содержимом ячейки: сетка
связывает его со своей осью сама, своего состояния у него нет. `MediaCard`
остаётся показом: проп `selected` ему передать можно, он рисует состояние, а
`onSelectedChange` не нужен.

**Кнопки в ячейке законны**: «в избранное», «скачать». Ячейка — `gridcell`, и
кнопка в ней не вложенный интерактив. Нажатие на кнопку не выбирает и не
открывает ячейку, **если кнопка из react-aria** — `Button` кита, `Button` или
`ToggleButton` из `react-aria-components`: ячейка ловит нажатие через
`usePress`, и только кнопка на `usePress` гасит его на себе. Обычный
`<button onClick>` отдаёт нажатие ячейке — клик по «в избранное» заодно открыл
бы карточку.

**Храните выбор как пришёл.** `onSelectionChange` отдаёт `Selection`
react-aria — `Set` с якорем Shift-диапазона на самом объекте. Передавайте его
обратно в `selectedKeys` без перекладывания: `new Set(keys)` теряет якорь, и
Shift+клик выделяет одну ячейку вместо диапазона. Исключение — `"all"` (⌘A в
сетке): его потребитель разворачивает в конкретный набор сам.

**До 3.1.0 здесь стояло обратное правило**: «выбор включается у `MediaCard`».
Оно было неисполнимо. Ячейка сетки была `option`, кнопка внутри `option` давала
вложенный интерактивный элемент, и axe справедливо звал это нарушением уровня
serious. С 3.47.0 ячейка — `gridcell`, и флажок выбора внутри неё законен — но
это флажок оси сетки, а не своё состояние карточки.

**Клик и выбор — `selectionBehavior`.** `toggle` (по умолчанию): клик
переключает ячейку, а если задан `onAction`, открывает её; выбирает тогда клавиша Пробел. `replace` —
как в файловом менеджере: клик выделяет одну ячейку, Ctrl/Cmd добавляет, а
открывают двойной клик и Enter.

**Диапазон по Shift — `rangeSelection`.** По правилу react-aria (`replace`) Shift
заменяет выбор диапазоном от якоря, и выбранное вне диапазона снимается. `add`
добавляет диапазон к прежнему выбору и ничего не снимает.

**Протяжка пальцем — `dragToSelect`.** Удержать ячейку и вести по соседним: они
добавляются диапазоном по порядку `items`; у края видимой области (или контейнера)
сетка прокручивается сама. Быстрый свайп — это прокрутка, а не жест: выделение
начинается после удержания и лишь тогда, когда палец перешёл на другую ячейку. Только
касание и только при `selectionMode="multiple"`. Жест не единственный путь к тому
же: флажок выбора и Shift со стрелками дают тот же результат с мыши и с клавиатуры.

## Действие над ячейкой — `onAction`

Кликом или Enter ячейку **открывают**, а не выбирают: просмотр, переход,
карточка записи. Для этого у сетки есть `onAction(id, { rect })`; выбор здесь ни
при чём. `rect` — прямоугольник ячейки в момент действия: карточку можно
вырастить «из места».

```tsx
<VirtualGrid
  items={items}
  aria-label="Файлы"
  onAction={(id, { rect }) => openPreview(String(id), rect)}
  className="h-[520px]"
/>
```

Без `selectionMode` ячейка не выделяется вовсе: `onSelectionChange` молчит,
`aria-selected` нет. Вместе с `selectionMode` работают и действие, и выбор по правилам
react-aria: клик и Enter вызывают `onAction`, а выбирает Пробел. Если клик
должен именно выбирать, не задавайте `onAction` или возьмите
`selectionBehavior="replace"`.

Не стройте «открыть» на `selectionMode="single"`, выбирая ячейку и открывая её
по смене выбора: повторный клик по той же ячейке тогда ничего не откроет, а
закрытие просмотра оставит ячейку выделенной.

## Контекстное меню ячейки — `contextMenu`

Поле `contextMenu` у ячейки (`items[n].contextMenu`) — пункты меню:
`ContextMenuItem`, `ContextMenuSeparator`, `ContextMenuSub` и остальное из
семейства [`ContextMenu`](../overlays/context-menu.md). Панель, триггер и
изоляцию от выбора сетка ставит сама, поэтому оборачивать ячейку в
`ContextMenu` вручную не нужно.

```tsx
import { ContextMenuItem, ContextMenuSeparator, VirtualGrid } from "@olddevs/ui";

<VirtualGrid
  items={files.map((f) => ({
    id: f.id,
    textValue: f.name,
    content: <MediaCard preview={<Image src={f.url} alt="" />} title={f.name} />,
    contextMenu: (
      <>
        <ContextMenuItem onSelect={() => rename(f)}>Переименовать</ContextMenuItem>
        <ContextMenuSeparator />
        <ContextMenuItem tone="danger" onSelect={() => remove(f)}>
          Удалить
        </ContextMenuItem>
      </>
    ),
  }))}
  aria-label="Файлы"
  className="h-[520px]"
/>;
```

Меню открывается правой кнопкой, долгим нажатием на сенсорном экране и с
клавиатуры — **Shift+F10** или клавишей контекстного меню на сфокусированной
ячейке (меню встаёт по центру ячейки). Закрытое меню возвращает фокус на ячейку.
Пункт меню не выбирает ячейку, не двигает по ней фокус и не вызывает `onAction`:
события панели гасятся на границе ячейки. Ячейка без `contextMenu` остаётся
прежней — без обёртки и без обработчиков.

**Долгое нажатие — только меню.** На сенсорном экране долгое нажатие на ячейку
с меню открывает меню и больше ничего: ячейка не открывается и не выделяется.
У react-aria для сетки с выбором и `onAction` есть правило «долгое нажатие
начинает выбор», и раньше оно срабатывало вместе с меню; теперь сетка гасит
его у ячеек с меню. У ячейки без меню правило react-aria остаётся: долгое
нажатие выделяет её. С `dragToSelect` споров нет: удержание только взводит
протяжку, палец поехал — меню не откроется, удержал — откроется меню, и
протяжка уже не начнётся.

**Почему не `ContextMenu` вокруг `content`.** Так делали до появления поля, и
выходило два сбоя. Первый: правая кнопка работает, а Shift+F10 нет, потому что
фокус стоит на ячейке, а триггер меню лежит внутри неё. Второй: события панели,
вынесенной порталом, всплывают по дереву React до ячейки и выбирают её. Оба
сбоя теперь закрыты внутри сетки.

Меню не заменяет видимых действий: ключевую операцию нельзя оставлять
доступной только по правому клику
([ContextMenu](../overlays/context-menu.md)).

## Антипаттерны

- В режиме `container` не задать высоту — прокручивать будет нечего.
- Ставить `scroll="container"` и обёртку с `overflow: auto` вокруг вместо
  `scroll="window"` на странице с прокруткой окна.
- Складывать в `content` тяжёлую ветку: она перерисовывается при прокрутке.
- Строить «открыть» на `selectionMode="single"` вместо `onAction`.
- Держать свой флажок выбора в состоянии карточки вместо `Checkbox slot="selection"`.
- Оборачивать `content` в свой `ContextMenu` вместо `contextMenu` ячейки:
  Shift+F10 не откроет меню, а клик по пункту выберет ячейку.
