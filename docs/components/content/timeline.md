# Timeline

## Кратко для AI

`Timeline` — лента шагов процесса: что уже произошло и чем закончилось. У каждого шага своё состояние, и любой может провалиться.

## Когда использовать

- Когда нужно наблюдать за идущим или завершившимся процессом: конвейер задачи, история публикации, шаги импорта.
- Когда шаг может закончиться отказом, и это надо показать рядом с ним, а не общим статусом сверху.

## Когда не использовать

- Для мастера из нескольких экранов — это `Stepper`: там линейный `current`, шаги впереди ещё не случались, провалиться не могут, а назад ведёт клик.
- Для одного состояния объекта — это `StatusBadge`.
- Для сообщения о сбое всей операции — это `Alert` или `ErrorState`.

Разница со `Stepper` не стилевая, и именно из-за неё конвейер шагов задачи в приложении-источнике не перешёл на `Stepper`, а остался рукописным:

|              | `Stepper`                     | `Timeline`          |
| ------------ | ----------------------------- | ------------------- |
| состояние    | одно на всю ленту (`current`) | своё у каждого шага |
| отказ шага   | не выражается                 | `status: "failed"`  |
| интерактивен | да, клик по пройденному шагу  | нет, это наблюдение |

## Минимальный пример

```tsx
import { Timeline } from "@olddevs/ui";

<Timeline
  aria-label="Шаги задачи"
  items={steps.map((s) => ({
    id: s.id,
    label: s.step_name,
    status: s.status,
    statusLabel: STATUS_LABEL[s.status],
    details: s.details,
  }))}
/>;
```

## Public API

| Prop         | Значение                                            |
| ------------ | --------------------------------------------------- |
| `items`      | Массив шагов. Пустой — компонент не рисуется вовсе. |
| `aria-label` | Имя ленты для скринридера.                          |
| `className`  | Классы обёртки.                                     |

Шаг: `id`, `label`, `status` (`pending` · `running` · `success` · `failed`), необязательные `statusLabel`, `details`, `time`.

**Подпись состояния — проп, а не вывод из `status`.** Слова «выполнен» и «ошибка» принадлежат предметной области: у задачи импорта и у платежа они разные. Сопоставление «статус → подпись» живёт у потребителя, рядом с доменом — так же, как у `StatusBadge`.

## Доступность

Разметка — упорядоченный список (`ol`): шаги идут по порядку, и скринридер обязан сообщить и порядок, и общее число. Набор `div` не сообщает ни того, ни другого. Идущий шаг помечается `aria-current="step"`; точки и соединительные линии декоративны и скрыты.

## Цвета

Цвета берутся из словаря тонов (`TONE_TOKENS`), а не задаются заново: «ошибка» означает один и тот же цвет здесь, в `Alert`, в `StatusBadge` и на кнопке удаления. `pending` намеренно нейтральный и приглушённый — шаг, который ещё не начинался, не событие.
