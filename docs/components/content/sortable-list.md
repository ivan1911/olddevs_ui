# SortableList

## Кратко для AI

Список, порядок которого задаёт пользователь перетаскиванием. Стоит на
`useDragAndDrop` из react-aria: объявления, клавиатура и точка вставки — оттуда.
Порядок компонент не хранит. Списки одной `group` обмениваются строками — так
собирается доска: переезд приходит в `onMove` списка-приёмника, состав колонок
держит экран.

## Когда использовать

- Порядок значим и задаётся человеком: разделы меню, шаги сценария, приоритет.
- Элементов немного, и они помещаются на экран.
- Доска: колонки-списки одной `group`, между которыми строку переносят мышью и с
  клавиатуры.

## Когда не использовать

- Для сортировки по значению колонки — это `Table`: там порядок вычисляется, а
  не назначается.
- Для сотен элементов: виртуализация и перетаскивание вместе в ките не
  проверены. Сетка с виртуализацией — `VirtualGrid`, перетаскивания в ней нет.
- Для дерева — это `TreeView`.

## Минимальный пример

```tsx
import { SortableList } from "@olddevs/ui";

const [items, setItems] = useState([
  { id: "1", label: "Обзор" },
  { id: "2", label: "Кампании" },
]);

<SortableList
  items={items}
  aria-label="Порядок разделов"
  onReorder={(ids) => setItems(ids.map((id) => items.find((i) => i.id === id)!))}
/>;
```

## Пропы

| Проп         | Умолчание | Назначение                                            |
| ------------ | --------- | ----------------------------------------------------- |
| `items`      | —         | Строки: `id`, `label`, `textValue`.                   |
| `onReorder`  | —         | Новый порядок целиком — список идентификаторов.       |
| `aria-label` | —         | **Обязателен.** Безымянный список объявляется пустым. |
| `emptyText`  | —         | Что показать, когда строк нет.                        |
| `group`      | —         | Группа списков, которые обмениваются строками.        |
| `id`         | —         | Имя списка в группе для `onMove`; в DOM не попадает.  |
| `onMove`     | —         | Строку принесли из другого списка группы.             |

## Ручка перетаскивания обязательна

У каждой строки есть кнопка-ручка, и её рисует сам компонент, а не потребитель
по желанию. Причина измерена: без `<Button slot="drag">` строка
получает `draggable="true"` и таскается мышью, **а с клавиатуры не берётся
вообще**. react-aria при этом не падает — она пишет предупреждение в консоль. То
есть недоступный список выглядит рабочим.

Имя ручки — только глагол (в русском каталоге «Перетащить», `sortableList.drag`): подпись строки библиотека дописывает
сама, и повторив её, мы услышали бы её дважды.

## Клавиатура

| Клавиша          | Что делает                         |
| ---------------- | ---------------------------------- |
| `→`              | Переводит фокус со строки на ручку |
| `Enter` на ручке | Начинает перетаскивание            |
| `↑` / `↓`        | Выбирает точку вставки             |
| `Enter`          | Применяет                          |
| `Escape`         | Отменяет                           |
| `Tab`            | Переходит к другому списку группы  |

Объявление react-aria предлагает выбирать цель по `Tab`. В одиночном коротком
списке `Tab` уводит фокус из кольца целей и **отменяет** перетаскивание —
проверено в браузере; ходите стрелками. В группе `Tab` ведёт к следующему
списку, и `Enter` кладёт строку туда — это тоже проверено в браузере.

## Своей живой области нет

react-aria объявляет перетаскивание сама и локализованно. Под русской локалью
замер дал: «Начато перетаскивание. Нажмите клавишу Tab для выбора цели…»,
«Вставить между Обзор и Кампании», «Перетаскивание завершено».

Своя живая область дублировала бы эти строки и спорила бы с ними. `DragAnnouncer`
из приложения-источника в кит не поднимается: он написан под `@dnd-kit`,
который молчит
(ADR-0028).

Чтобы объявления пришли по-русски, у `UiProvider` должна быть задана `locale`:
именно она разворачивает `I18nProvider` react-aria.

## Порядок не хранится внутри

`onReorder` отдаёт **весь новый порядок**, а не «что куда переехало»: применить
готовый список проще, чем восстановить его из события, и ошибиться негде. Обязанности
разделены так же, как у сортировки таблицы
(ADR-0023).

## Перенос между списками

Списки с одной `group` обмениваются строками: колонки доски, «доступные» и
«выбранные». Список без группы, как и прежде, только переставляет свои строки.

```tsx
import { SortableList, type SortableMove } from "@olddevs/ui";

// Состав колонок — одно состояние экрана: строка уходит из `from`
// и встаёт в `to` на `index` за один шаг.
const move = ({ id, from, to, index }: SortableMove) =>
  setBoard((board) => moveRow(board, id, from, to, index));

{
  columns.map((column) => (
    <SortableList
      key={column.id}
      id={column.id}
      group="board"
      aria-label={column.label}
      items={column.items}
      onReorder={(ids) => reorderIn(column.id, ids)}
      onMove={move}
    />
  ));
}
```

- Принимает строки только список с `onMove`; отдавать их умеет любой список
  группы.
- `onMove` вызывается у списка-**приёмника** и сообщает `id` строки, `from`,
  `to` и `index` — место в приёмнике. Внутри своего списка по-прежнему работает
  `onReorder`.
- Состав списков компонент не хранит, как и порядок: обновлять оба списка — дело
  экрана: состояние доски одно, поэтому строку нужно убрать из одного списка и
  поставить в другой за один шаг.
- Пустой список принимает строку броском на сам список — покажите в нём
  `emptyText`, чтобы было видно, куда бросать.
- Чужая группа строку не примет: у каждой группы свой тип данных
  перетаскивания. Файл с рабочего стола список тоже не возьмёт.
- `id` списка — ключ состояния, а не `id` элемента: в DOM он не попадает и со
  страницей не столкнётся.

## Значок копирования в WebKit: известное, чинить нечем

В Safari и других сборках WebKit в самом начале перетаскивания на долю секунды
появляется системная иконка «будет создана копия» — зелёный кружок с плюсом.
Список копировать строки не умеет, и ничего не копируется: иконка врёт.

Починить это со стороны кита или потребителя нельзя. Компонент
объявляет единственную разрешённую операцию — `getAllowedDropOperations: () =>
["move"]`. Замер обоих движков показывает, что объявление применяется:
`effectAllowed` записывается и читается обратно как `move`, а react-aria вдобавок
пишет `dropEffect: move` на каждом `dragover` — 24 записи за одно перетаскивание,
и в обоих движках они принимаются. Chromium это соблюдает: приёмник видит `move`, перетаскивание
заканчивается с `move`, иконки нет.

WebKit теряет объявление на уровне сессии перетаскивания и отдаёт приёмнику
`all` — [баг 178058](https://bugs.webkit.org/show_bug.cgi?id=178058), известный
с 2017 года. `all` включает копирование, и операционная система рисует «плюс»,
пока первый же приёмник не переубедит её обратно. Отсюда и мелькание: это окно
между чужим умолчанием и первой поправкой.

**Перестановка при этом верна.** react-aria держит настоящий набор операций в
своей переменной и пересекает его с тем, что вернул браузер; это его штатный
обход того же бага. Замер в WebKit: пять строк до броска, пять после, порядок
изменился ровно так же, как в Chromium. Строка не удваивается.

Что не помогает (проверять заново не нужно):

- **своё превью перетаскивания** (`renderDragPreview`). Неверное значение видно
  в контракте данных, в `effectAllowed` у приёмника, а не в картинке. Превью
  на маску операций не влияет;
- **отказ от `text/plain`**. Значок появляется на первом же `dragenter` по самому
  списку, до любого текстового поля на странице, а в Chromium с тем же
  `text/plain` его нет;
- **снятие `getAllowedDropOperations`**. Сделает хуже: тогда копирование будет
  разрешено уже по-настоящему, и иконка станет правдой.

## Антипаттерны

- Прятать ручку «чтобы было чище»: без неё список недоступен с клавиатуры.
- Заводить свою живую область поверх объявлений react-aria.
- Хранить порядок внутри компонента.
- Переносить строку между колонками своим меню вместо `group`: меню годится как
  запасной путь, но не как единственный.
- Обновлять в `onMove` только список-приёмник: строка окажется в двух колонках
  сразу.
