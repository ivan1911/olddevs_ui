# ConfirmDialog

## Кратко для AI

`ConfirmDialog` подтверждает значимое или необратимое действие. Он уже собран на
`Dialog` с `role="alertdialog"`, ставит начальный фокус на подтверждающую кнопку
и не требует вручную строить модальность или порядок фокуса. Для самых опасных
действий (удалить пространство, проект, аккаунт) умеет подтверждение вводом:
`typeToConfirm="Acme"` — кнопка выключена, пока пользователь не набрал название.

## Когда использовать

- Удаление, снятие с публикации, немедленная отправка и другие действия, которые
  пользователь должен подтвердить отдельно.
- Короткий вопрос в `title`, пояснение в `message` и явные `onConfirm`/`onClose`.

## Когда не использовать

- Для ввода данных в несколько полей, просмотра или нейтральной настройки — `Dialog`.
- Для некритичной операции, которую можно отменить после выполнения, — действие
  плюс `toast`, не лишнее подтверждение.
- Не выбирайте цвет кнопки вручную: смысл задаёт `kind`.

## Минимальный пример

```tsx
<ConfirmDialog
  open={deleteOpen}
  onClose={() => setDeleteOpen(false)}
  onConfirm={removeUser}
  title="Удалить пользователя?"
  message="Действие необратимо."
  confirmLabel="Удалить"
/>
```

## Подтверждение вводом имени

```tsx
<ConfirmDialog
  open={deleteOpen}
  onClose={() => setDeleteOpen(false)}
  onConfirm={removeWorkspace}
  title="Удалить пространство?"
  message="Будут удалены все проекты, файлы и участники."
  confirmLabel="Удалить пространство"
  typeToConfirm={workspace.name}
/>
```

`typeToConfirm` — строка, которую надо набрать. Когда она задана, в окне
появляется поле с подписью `Введите «Acme», чтобы подтвердить` и пояснением под
ним. Фокус при открытии встаёт в поле (а не на кнопку), кнопка подтверждения
выключена, пока набранное не совпало. Enter в поле подтверждает только при
совпадении.

- **Регистр важен.** Смысл приёма в том, чтобы пользователь прочёл название и
  набрал именно его: «acme» вместо «Acme» отличает одно пространство от другого,
  и пояснение под полем говорит об этом прямо.
- **Пробелы по краям набранного не считаются**, потому что вставка из буфера
  часто приносит лишние пробелы по краям; пробелы внутри названия значимы. Сверка идёт в
  канонической форме Unicode (NFC): «é» одной буквой и «e» с акцентом равны.
- **Пустая строка — не название.** `typeToConfirm=""` (и строка из одних
  пробелов) поля не включает: окно подтверждается как обычно, без поля-замка.
- Набранный текст живёт внутри окна и после закрытия не сохраняется;
  `onConfirm` вызывается уже после совпадения, проверять совпадение самостоятельно не нужно.
- Подпись и пояснение — из каталога сообщений
  (`confirmDialog.typeToConfirm`, `confirmDialog.typeToConfirmHint`) с русским
  переводом и английским фолбэком. При `loading` поле
  становится «только для чтения» (фокус остаётся в нём), кнопки блокируются.

Окно остаётся `alertdialog`: поле здесь замок, а не ввод данных. Нужны другие
поля, проверка на сервере или своя разметка формы — это `Dialog`.

## Public API

Обязательны `open`, `onClose`, `onConfirm`, `title` и `message`. Тексты кнопок
берутся из каталога сообщений (`confirmDialog.confirm`,
`confirmDialog.cancel`): без провайдера «Confirm» и «Cancel», с русской локалью —
«Подтвердить» и «Отменить»; пропы переопределяют точечно. `kind` принимает `danger` (умолчание),
`warning` или `info`: это семантика вопроса, а не произвольная палитра. Для
`info` подтверждение акцентное; для двух остальных — контурная кнопка в тоне `danger`.

`typeToConfirm` — необязательная строка подтверждения вводом, см. раздел выше.

`loading` блокирует обе кнопки и передаётся в базовый `Dialog`, поэтому окно
нельзя закрыть крестиком, Escape или щелчком вне окна до завершения операции.

## Доступность и клавиатура

Компонент создаёт `alertdialog`, а не обычный `dialog`, и фокусирует кнопку
подтверждения через `initialFocusRef`; с `typeToConfirm` фокус встаёт в поле
ввода. Пояснение под полем связано с ним через `aria-describedby`, а сам вопрос
остаётся описанием диалога. Формулируйте `title` как вопрос, а
`confirmLabel` как конкретное действие («Удалить», не «ОК»). Не вызывайте
`onClose` из `onConfirm`, пока асинхронное действие ещё не завершено: вместо
этого управляйте `loading` на стороне потребителя.

## Хорошие примеры

- `kind="danger"`, «Удалить», для безвозвратной операции.
- `kind="warning"`, «Снять», для заметного, но обратимого изменения.
- `kind="info"`, «Опубликовать», для явного подтверждения обычного действия.

## Антипаттерны

- Подтверждать каждое сохранение или переключатель.
- Передавать в `message` единственную фразу «Вы уверены?», не назвав последствия.
- Открывать второе подтверждение при `loading` первого.
- Ставить `typeToConfirm` на каждое удаление: замок нужен там, где ошибка стоит
  дорого, иначе пользователь привыкает набирать, не читая.
- Собирать подтверждение вводом на `Dialog` с ручной сверкой — это и есть то,
  что делает `typeToConfirm`.
