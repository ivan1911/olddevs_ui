# Slider и RangeSlider

## Кратко для AI

`Slider` задаёт одно число, `RangeSlider` — границы `[min, max]`. Это управляемые контролы React Aria с поддержкой клавиатуры. `Slider` бывает горизонтальным (по умолчанию) и вертикальным, `RangeSlider` — только горизонтальным.

## Когда использовать

- Значение естественно воспринимается как место на шкале: громкость, прозрачность, числовой фильтр.
- Для диапазона нужны два конца и, при необходимости, минимальный зазор `minGap`.
- Вертикальный `Slider` — когда значение читается как уровень: громкость, усиление, заполненность. Несколько таких ползунков рядом складываются в пульт.

## Когда не использовать

- Для точного ввода значения без визуальной шкалы используйте `NumberInput`.
- Для одного из дискретных текстовых вариантов используйте `Select`/`RadioGroup`.
- Не ставьте вертикальный `Slider` в форму ради экономии ширины: в столбце полей горизонтальный встаёт в один ряд с соседями, а вертикальный выглядит ошибкой вёрстки.
- Вертикального `RangeSlider` нет: `orientation` у него отклоняется на уровне типа.

## Минимальный пример

```tsx
<Slider label="Прозрачность" value={opacity} onChange={setOpacity} minValue={0} maxValue={100} />
<RangeSlider label="Цена" value={price} onChange={setPrice} minValue={0} maxValue={1000} minGap={50} />
<Slider label="Уровень" orientation="vertical" value={level} onChange={setLevel} formatValue={(v) => `${v}%`} />
```

## Public API

- Props наследуют React Aria Slider: `value`/`defaultValue`, `onChange`, `minValue`, `maxValue`, `step`, `isDisabled`.
- `label` именует контрол; `valuePosition` — `side` (по умолчанию) либо `none`; `formatValue` форматирует значение для скринридера.
- `Slider.orientation` — `horizontal` (по умолчанию) или `vertical`. У `RangeSlider` этого пропа нет.
- `RangeSlider.minGap` предотвращает диапазон меньше указанного. Если начальные значения уже нарушают `minGap`, компонент сдвигает конец, которого пользователь не касался, при следующем изменении: тот, что под пальцем, остаётся на месте.
- **С `minGap` держите `RangeSlider` управляемым** (`value` + `onChange`). У неуправляемого зажатая пара уходит только в `onChange`, а внутреннее состояние react-aria остаётся незажатым: на экране концы могут встать ближе, чем `minGap`, хотя в `onChange` ушло правильное значение. Кит выправить это у себя не может — состоянием там владеет библиотека.

## Вертикальный Slider

- Заливка растёт от нижнего края: «больше» на вертикальной шкале — выше.
- Высоту задаёт корень: по умолчанию `h-48`, своя — через `className` (`className="h-64"`). Без высоты вертикальной дорожке не во что тянуться.
- Подпись и значение стоят над дорожкой, как у горизонтального; `valuePosition` и `formatValue` работают так же. Ширина ползунка — по ширине шапки (подписи и значения над дорожкой), а не на всю ширину контейнера.
- Почему вертикали нет у `RangeSlider`: геометрия заливки между двумя концами по высоте не сделана, а проп, который компилируется и ничего не делает, хуже отсутствующего. Понадобится — это отдельная задача.

## Доступность и клавиатура

- React Aria реализует pointer/touch, стрелки на шаг, Shift для крупного шага и Home/End для границ.
- Колесо мыши и тачпад над ползунком двигают значение на шаг: вверх увеличивает, вниз уменьшает (на горизонтальном боковая прокрутка вправо тоже увеличивает). У `RangeSlider` двигается конец, ближайший к курсору, с учётом `minGap`. На границе шкалы колесо отдано странице, чтобы прокрутка не «залипала» на ползунке; при `isDisabled` колесо не работает.
- У вертикального бегунок объявляет `aria-orientation="vertical"`; стрелка вверх увеличивает значение, вниз — уменьшает.
- С `isDisabled` ползунок приглушается целиком, как прочие поля кита: подпись, значение, дорожка и бегунок; тянуть и фокусировать его нельзя.
- Не скрывайте значение, если рядом нет другого понятного отображения.
