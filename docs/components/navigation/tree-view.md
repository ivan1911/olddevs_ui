# TreeView

## Кратко для AI

Иерархия с раскрытием, выбором и клавиатурой на `Tree` из react-aria.
Состояний не хранит: раскрытые и выбранные узлы приходят множествами. Режим
выбора включается `selectionMode` — без него флажков нет вовсе. Текущий узел
навигации (дерево статей) отмечается `activeKey` — это `aria-current="page"`
без флажков и без выбора.

## Когда использовать

- Дерево категорий, папок, разделов справки, структуры организации.
- Список, где вложенность существенна и её нужно раскрывать.
- Навигация по дереву статей, разделов, документов: открытая страница
  отмечена `activeKey`, переход делает `onAction`.

## Когда не использовать

- Для плоского списка с выбором используйте `Select` или `CheckboxGroup`.
- Для выбора из иерархии в поле — такого компонента (`TreeSelect`) в ките нет:
  он собирается из `TreeView` и `Popover`, а заводить его без экрана-заказчика —
  значит проектировать вслепую
  (ADR-0024).

## Минимальный пример

```tsx
import { TreeView, type TreeNode } from "@olddevs/ui";

const items: TreeNode[] = [
  { id: "nature", label: "Природа", children: [{ id: "forest", label: "Лес" }] },
  { id: "city", label: "Город" },
];

const [expanded, setExpanded] = useState<Set<Key>>(new Set(["nature"]));

<TreeView
  items={items}
  aria-label="Категории"
  expandedKeys={expanded}
  onExpandedChange={setExpanded}
/>;
```

## Пропы

| Проп                  | Умолчание | Назначение                                                                                                       |
| --------------------- | --------- | ---------------------------------------------------------------------------------------------------------------- |
| `items`               | —         | Узлы: `id`, `label`, опционально `icon`, `children`, `disabled`; `textValue` обязателен, если `label` не строка. |
| `aria-label`          | —         | Имя дерева. Обязательно, проверяет компилятор.                                                                   |
| `expandedKeys`        | —         | Раскрытые узлы. Дерево их не хранит.                                                                             |
| `onExpandedChange`    | —         | Колбэк получает множество раскрытых узлов.                                                                       |
| `defaultExpandedKeys` | —         | Раскрытые при первом показе; дальше ведёт react-aria.                                                            |
| `selectionMode`       | —         | Включает режим выбора: `single` или `multiple`.                                                                  |
| `selectedKeys`        | —         | Выбранные узлы.                                                                                                  |
| `onSelectionChange`   | —         | Колбэк получает выбранные узлы.                                                                                  |
| `disabledKeys`        | —         | Недоступные узлы.                                                                                                |
| `activeKey`           | —         | Текущий узел навигации: `aria-current="page"` и подложка.                                                        |
| `onAction`            | —         | Действие по узлу: переход, открытие. Выбором не является.                                                        |
| `emptyText`           | —         | Что показать, когда узлов нет.                                                                                   |

## Роль — `treegrid`, а не `tree`

Так решил react-aria, и решение обоснованное: в строке живут кнопка раскрытия и
флажок, а `treeitem` второго интерактивного элемента внутри себя не
предполагает. У узлов роль `row` с `aria-level`, `aria-expanded`,
`aria-posinset` и `aria-setsize`.

Переопределять роли руками кит не станет: тогда клавиатура из слоя поведения
перестала бы соответствовать разметке. В тестах узлы и ищутся по
роли `row` — это не обход, а точное отражение того, что видит скринридер.

## Состояний не хранит, `useTreeData` наружу не идёт

Правило то же, что у `Table`: раскрытые и выбранные приходят множествами
(ADR-0023).

`useTreeData` из react-aria кит **не** реэкспортирует. Это хранилище, а кит
состоянием не владеет; кому нужно готовое — берёт его из
`react-aria-components` напрямую, и тогда это его выбор, а не навязанный китом.

## Режим выбора включается `selectionMode`

Без него ни флажков, ни `aria-selected` в разметке нет: дерево категорий, по
которому просто ходят, не должно тащить колонку выбора. То же правило, что у
`Table`.

`onAction` выбором не является: это переход или открытие карточки.

## Текущий узел: `activeKey`

Дерево навигации (база знаний, структура разделов) показывает «вы здесь», а
не набор отмеченного. Режим выбора для этого не годится: `selectionMode` рендерит
флажок в каждой строке и выставляет `aria-selected`, а текущая страница — это
место, а не выбор. Поэтому отдельный проп:

```tsx
<TreeView
  items={articles}
  aria-label="Статьи"
  activeKey={articleId}
  onAction={(id) => openArticle(id)}
/>
```

- Узел с ключом `activeKey` получает на строке `aria-current="page"` и
  подложку `bg-3` с полужирной подписью, как у `NavItem` с `active`. Если ключа нет
  среди узлов или проп не задан, ничего не отмечается.
- Дерево **само «текущее» не переставляет**: клик по листу вызывает `onAction`, а
  новый `activeKey` присылает потребитель, когда сменился маршрут. Так же, как
  выбор и раскрытие, это значение, а не состояние кита.
- Флажков нет, `aria-selected` нет. С `selectionMode` текущий узел и выбор
  можно держать вместе — это два независимых набора.
- Узел внутри свёрнутой папки в разметке отсутствует, и отметки у него нет,
  пока папку не раскроют. Раскрыть путь до открытой статьи — забота
  потребителя через `expandedKeys`.

**Имя — `activeKey`, а не `currentKey` и не `selectedKey`.** По словарю кита
([conventions.md](../../conventions.md)) `active` занят одним смыслом: текущий
пункт навигации, `aria-current="page"`; `selected` — выбор в наборе. Дерево
хранит не пункты, а данные по ключам, поэтому булев `active` на узле здесь не
годится: по образцу `selectedKeys`, `expandedKeys` и `disabledKeys` проп
принимает ключ. Одно значение, а не набор: страница в навигации одна.

## Действие по папке не раскрывает её

Когда задан `onAction`, клик по строке-папке вызывает `onAction` с
её ключом — но **папку не раскрывает**. Папку раскрывают шеврон и стрелка вправо
(сворачивает стрелка влево), то есть жесты раскрытия и действия разведены: это
поведение `Tree` из react-aria, кит его не меняет. Без `onAction` клик по строке
раскрывает папку.

Если по клику на папку дерево должно раскрываться, это делается в самом `onAction`:
определить, что у узла есть дети, и обновить свой `expandedKeys`.

```tsx
onAction={(id) => (isFolder(id) ? toggle(id) : openArticle(id))}
```

## Клавиатура и имена

Стрелки, Home, End, поиск набором и раскрытие приходят из слоя поведения
(ADR-0005),
а не пишутся руками; проверяются они в живом браузере.

Имя кнопки раскрытия — только глагол: «Раскрыть» у свёрнутого узла и «Свернуть» у
раскрытого, **без** подписи узла: react-aria
дописывает её сам, и «Раскрыть Природа» читалось бы как «Раскрыть Природа
Природа». Тот же дефект ревью волны 18 нашло у `TagInput` и `FilterBar`.

Отступ уровня берётся из переменной `--tree-item-level`, которую react-aria
кладёт на строку: считать глубину самим — значило бы держать вторую копию того
же числа. Шаг отступа — `--tree-indent`.
