Editor, extension: Date mention. The new `date` Tool, in `full` (not in `basic`), puts a date inside a line of text as an inline Atom, `<time datetime="…">text</time>`. The Slash menu item "Date" opens a Popover with the kit's `Calendar` (focus on today, so `Enter` inserts today) and a "Time" switch with a time field; a click or `Enter` on a mention edits it ("Remove time", "Delete date"). The value is `YYYY-MM-DD` or, with a time, `YYYY-MM-DDTHH:MM±HH:MM` with the author's UTC offset; a date without a time has no zone. The text is written in the author's locale when the mention is inserted or edited, so `RichTextView` shows it as it is, with no JS and no hydration difference. The calendar and the Popover are a lazy chunk. The option is `tool("date", { format })` (an `Intl.DateTimeFormatOptions` object for the date), the command is `handle.tool("date")?.insert(value?)`, and the new types are `DateToolOptions` and `DateToolCommands`, the icon is `DateMentionIcon`, and seven `editor.date*` strings join the message catalog. The Schema and `sanitizeRichText` now allow `time[datetime]` with a strict, calendar-checked value; someone else's `<time>` in that form becomes a mention, and in any other form stays text. In Markdown a mention is its text and the machine value is lost.
