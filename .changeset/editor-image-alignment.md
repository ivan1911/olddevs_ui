Editor, extension: image alignment and text wrapping. An image can now stand at the left or the right edge with the text of the next Blocks wrapping around it, as in Word; the centre stays the default. It is part of the `image` Tool, so there is no new Tool and no Option, and the selected image's panel and its "Edit image" popover gain three toggles (left, centre, right) before the widths. `Ctrl/⌘+Shift+L`, `+E` and `+R` align a selected image instead of the text; with the caret anywhere else they align text as before. The image width presets are now 25, 33, 50, 75 and 100%. Wrapping needs room, so an aligned image is always narrower than its container: choosing Left or Right on an image at its own size or at 100% sets 50% in the same edit, and 100% on an aligned image puts it back in the centre. A Document narrower than 30 rem keeps the image on a line of its own, and a table cell takes no alignment. An aligned image has one resize handle, on the side of the text, that follows the mouse one pixel for one and snaps to 25, 33, 50 or 75%. A heading, table, code block, divider, centred image, Column layout, Wrapper, Details Block, video and the footnote list start below the image. A paste from Word or from a web page keeps the side of a picture (`align`, `float`, Word's `mso-wrap-style`, the WordPress classes `alignleft` and `alignright`), and a width given as a percentage goes to the nearest preset, any other size to 50%. Markdown loses the position, as it loses the width and the caption, and the JSON envelope keeps it. New message catalog strings: `editor.imageAlign`, `editor.imageAlignLeft`, `editor.imageAlignCenter` and `editor.imageAlignRight`.

The saved HTML can now carry `figure[data-align="left|right"]`, and `img[data-width]` can be `25` or `33`. `sanitizeRichText` allows both, so a server that already sanitizes with it needs no change; a server with its own allowlist built from `RICH_TEXT_SCHEMA` must add `figure[data-align]` and the two widths (`RICH_TEXT_SCHEMA.attributes.figure`, `imageAlignments` and `imageWidths`). The visible change for an existing Document: an image that already carries `data-width="25"` or `"33"` used to lose it and keep its own size, and now it is shown at that width.
