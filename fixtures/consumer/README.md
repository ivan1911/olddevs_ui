# Фикстура-потребитель

Приложение на Next.js App Router, которым проверяется, что пакет годен снаружи.
Запускается из корня репозитория:

```bash
npm run check:consumer
```

Пакет ставится **тарболом** `npm pack`, а не алиасом на `src`: алиас проверял бы
исходники, то есть не то, что уезжает в реестр, — и был бы зелёным независимо от
содержимого пакета.

Что доказывает сборка:

- компонент кита импортируется прямо в серверный компонент, без обёртки;
- чистые утилиты (`cn`, `tableStateToParams`) считаются на сервере;
- классы компонентов доезжают до CSS потребителя через `@source`;
- подпуть `@olddevs/ui/editor` работает из серверного компонента: страница
  `/editor` чистит документ `sanitizeRichText` с DOMPurify на jsdom,
  подсвечивает `highlightCodeBlocks` и рисует `RichTextView` с блоком кода —
  скрипт читает её пререндер и требует токены подсветки и остров «Копировать»
  без единой подделки из документа, а `First Load JS` страницы держит свой
  бюджет (без строки `@olddevs/ui/editor` в `optimizePackageImports` — 435 кБ
  вместо 137);
- `RichTextEditor` с пресетом `full` рендерится прямо из серверного компонента
  (страница `/rich-text-editor`): ленивые чанки блока кода и таблицы собираются
  из `dist` отдельными файлами, а `First Load JS` страницы держит свой бюджет;
- подключение из [`docs/getting-started.md`](../../docs/getting-started.md)
  работает дословно — расхождение документации и фикстуры роняет сборку.

`Alert` на странице стоит пробой на потерю `"use client"`: он зовёт хук в теле, и
без директивы сборка падает сообщением «useMessages is on the client». Одной
`Button` для такой пробы **недостаточно** — хуков у неё нет, и без директивы она
молча отрендерилась бы на сервере. Это проверено нарочной поломкой, а не
предположением.

Опциональные peer-зависимости редактора (Tiptap, `lowlight`, `highlight.js`,
`marked`) фикстура ставит сама — ровно одной командой со страницы
`RichTextEditor`, как настоящий потребитель подпути; `dompurify` и `jsdom` —
санитайзер сервера, его кит тоже не ставит.

Свои зависимости и свой `package.json`: в `package.json` кита они не попадают, и
обещание «одна прямая зависимость и двенадцать peer» остаётся в силе. Сам кит в
зависимостях фикстуры **не объявлен** — он ставится с `--no-save`, поэтому
lock-файл не переписывается на каждый выпуск.

Решение и замеры — ADR-0029.
